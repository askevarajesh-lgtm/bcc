# Skill: Builder On-Page Metadata Optimization

You are turning a Website Builder page's measured metadata signals (its
current `<title>`, current `<meta name="description">`, its canonical
tag, its path, its own heading/body text, and — when relevant — the
title/description another page on the same site already uses) into a
new title tag and/or meta description. This is used on pages authored
in the site's drag-and-drop builder, which are frequently still in
Draft status and have never been crawled — so the only signal you have
is what is actually stored for this page and its siblings, never a live
SERP snippet.

## Golden rule

Ground every proposal only in the page's own path, its H1/heading text,
and its visible body copy (given to you as plain extracted text, not
raw HTML). Do not invent a product, offer, price, or claim the page
content doesn't support. If the page's content gives you too little to
work with, write a plain, honest title/description that reflects only
what's there — never pad with generic marketing filler to hit a length
target.

## Title tag

1. **Length: roughly 30–60 characters.** Long enough to be descriptive,
   short enough that search engines don't truncate it.
2. **Lead with the specific thing this page is about** (drawn from its
   H1 or path segment), not the site name alone.
3. Include the site/brand name only if room remains after the specific
   part — and only once.
4. Never propose the exact same title already used by another page on
   this site — that's the `duplicate_title` finding this skill exists
   to fix. Differentiate using what is actually distinct about this
   page's content.
5. No ALL CAPS, no keyword stacking separated by pipes/commas beyond one
   natural brand suffix.

## Meta description

1. **Length: roughly 70–160 characters.**
2. Written as a natural, single- or two-sentence summary of what a
   visitor will find on the page — not a repeat of the title, not a
   keyword list.
3. Never propose the exact same description already used by another
   page on this site — same duplication concern as the title.
4. Do not fabricate a call-to-action, price, or guarantee the page body
   doesn't mention.

## What NOT to do

- Do not propose a title or description for a finding type that wasn't
  actually flagged for this page — only the finding types listed as
  eligible for this page's run are ones you may address.
- Do not restate the current (flagged-as-bad) title/description
  verbatim and call it fixed — the whole point is a genuinely different,
  better string.
- Do not describe page structure issues (missing/duplicate H1s, skipped
  heading levels, missing canonical, thin content) with a title or
  description value — those are structural findings; give a short,
  concrete rationale/recommendation sentence for those instead, with an
  empty proposed value.
