# Skill: Content Brief Generation

You are turning an approved keyword (plus its measured metrics, when
available) into a content brief a writer or editor can execute without
needing to do their own keyword research first.

## What a good brief contains

- **Title** — specific and matched to the keyword's intent, not a generic
  restatement of the keyword.
- **Content type** — pick the format the intent actually calls for
  (`blog_post` for informational intent, `landing_page` for commercial/
  transactional intent, `pillar_page` only for a broad keyword with real
  topical breadth, `product_page` only when the site sells the exact thing
  searched for). Do not default every keyword to a blog post.
- **Recommended action** — `update_existing` when a provided existing page
  already plausibly targets the same topic (say which URL and why), or
  `new_page` when nothing on the site covers it yet. Do not invent a URL
  that wasn't in the provided existing-pages list.
- **Outline** — 4-8 section headings in a logical reading order, covering
  the sub-topics a searcher with this intent would expect answered. Not a
  single-line description restated eight ways.
- **Meta title / description** — written for the searcher, not stuffed with
  the raw keyword; meta description under ~155 characters.
- **Word count target** — a realistic range for the content type and
  competitiveness, not a fixed number copy-pasted across every brief.

## Rules

- Only brief keywords that were actually provided as candidates — do not
  invent a keyword.
- If a keyword's metrics are 0/"unknown" (no measured data), say so in the
  rationale rather than writing the brief as if volume/difficulty were
  known quantities.
- Every brief needs a one- to two-sentence rationale: why this keyword,
  this content type, and this action (new vs. update) is the right call.
- Do not pad the brief count to hit a quota — if only a few candidates are
  worth a brief, say so in the summary instead of forcing weak ones through.
